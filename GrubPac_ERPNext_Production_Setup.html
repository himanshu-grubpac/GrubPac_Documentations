9 Fix Database Permissions MariaDB Done

Why needed: ERPNext auto-generates a database user (e.g., _73c82ec6d255ebe3) but only grants access from localhost. Docker containers connect from a different IP, so we need to grant access from % (any host within the Docker network).

9.1 Get Site DB Credentials

$ sudo docker compose exec backend cat sites/erp.localhost/site_config.json

# Note the db_name and db_password values

9.2 Grant DB User Access

# Replace DB_NAME and DB_PASSWORD with actual values
$ sudo docker compose exec db mysql -uroot -padmin -e \
  "CREATE USER IF NOT EXISTS 'DB_NAME'@'%' IDENTIFIED BY 'DB_PASSWORD'; \
   GRANT ALL PRIVILEGES ON DB_NAME.* TO 'DB_NAME'@'%'; \
   FLUSH PRIVILEGES;"

9.3 Enable Scheduler & Set Default Site

$ sudo docker compose exec backend bench --site erp.localhost enable-scheduler
$ sudo docker compose exec backend bench use erp.localhost
$ sudo docker compose exec backend bench --site erp.localhost set-config host_name "http://13.201.123.135"
$ sudo docker compose restart

11 System Architecture

11 Docker containers running on a single EC2 instance, orchestrated by Docker Compose. All containers communicate via an internal Docker bridge network (erpnext-network). Only port 80 is exposed to the internet.

Python Backend

Image: frappe/erpnext:v15
Frappe/ERPNext application server. Handles all business logic, REST API, and database operations. The core of the system.

Nginx Frontend

Image: frappe/erpnext:v15 | Port: 80 → 8080
Nginx reverse proxy. Serves static assets, proxies API requests to backend, handles WebSocket connections. The only container exposed to the internet.

Node.js WebSocket

Image: frappe/erpnext:v15
Socket.IO server for real-time notifications, live updates, and collaborative editing within ERPNext.

MariaDB Database

Image: mariadb:10.6 | Buffer: 2GB | Log: 256MB
Primary database. Stores all ERPNext data — users, transactions, invoices, inventory, settings. Enterprise-grade, used by Google, Wikipedia, Samsung.

Redis Cache × 3

Image: redis:alpine | 3 instances
redis-cache: Application data cache. redis-queue: Background job queue broker. redis-socketio: Real-time WebSocket message routing.

Workers × 3 + Scheduler

Image: frappe/erpnext:v15 | 4 containers
queue-default: Standard jobs. queue-short: Quick tasks. queue-long: Heavy operations (imports, reports). scheduler: Cron tasks (email, auto-close).

13 EC2 Instance Protection Security Done

Purpose: Prevent accidental deletion or stopping of the production server. Once enabled, the instance cannot be terminated or stopped without first disabling the protection — an intentional two-step process.

ProtectionHow to EnableStatus
Termination Protection AWS Console → EC2 → Select instance → Actions → Instance Settings → Change Termination Protection → Enable ✓ Enabled
Stop Protection AWS Console → EC2 → Select instance → Actions → Instance Settings → Change Stop Protection → Enable ✓ Enabled
Result: Nobody can accidentally delete or stop the instance. Both protections must be manually disabled before any destructive action.

15 Automated Backups Backup Done

Schedule: Daily at 2:00 AM UTC (7:30 AM IST). Runs automatically — no manual intervention needed. Backups are stored locally on EC2 (7-day retention) and uploaded to S3 (30-day retention).

What's Included in Each Backup

Backup FileContainsSize
Database SQL (.sql.gz)All 700 tables — users, transactions, invoices, customers, items, settings, everything~850 KB
Private Files (.tar)Uploaded attachments, PDFs, letterheads, logos, imported CSVs~10 KB
Public Files (.tar)Website images, public assets uploaded via ERPNext~10 KB

Backup Script

# Location: /home/ubuntu/backup-erpnext.sh

#!/bin/bash
BACKUP_DIR="/home/ubuntu/backups"
S3_BUCKET="s3://grubpac-erpnext-backups"
DATE=$(date +%Y-%m-%d_%H-%M)
mkdir -p $BACKUP_DIR/$DATE

# Backup ERPNext site (database + files)
cd /home/ubuntu/erpnext
sudo docker compose exec -T backend bench --site erp.localhost backup --with-files

# Copy backups from Docker volume to host
CONTAINER_ID=$(sudo docker compose ps -q backend)
sudo docker cp $CONTAINER_ID:/home/frappe/frappe-bench/sites/erp.localhost/private/backups/ $BACKUP_DIR/$DATE/

# Upload to S3
aws s3 sync $BACKUP_DIR/$DATE/ $S3_BUCKET/$DATE/

# Cleanup: local 7 days, S3 30 days
find $BACKUP_DIR -type d -mtime +7 -exec rm -rf {} +

echo "[$DATE] Backup completed and uploaded to S3"

One-Shot Manual Update Script

Save as ~/update-erpnext.sh on the server. Run with: bash ~/update-erpnext.sh
CRITICAL: After every bench build, asset symlinks MUST be resolved to real files. Otherwise the frontend container cannot serve them (broken display).
#!/bin/bash
# GrubPac ERPNext Manual Update Script
# Includes: backup, pull, recreate, HRMS reinstall, build, symlink fix

SITE="erp.localhost"
COMPOSE_DIR="/home/ubuntu/erpnext"
CONTAINER="erpnext-backend-1"
HRMS_BRANCH="version-16"

# 1. Backup
sudo /home/ubuntu/backup-erpnext.sh

# 2. Pull + recreate
cd $COMPOSE_DIR
docker compose pull
docker compose up -d
sleep 20

# 3. Configure site
docker exec $CONTAINER bench use $SITE
docker exec $CONTAINER bash -c "cd /home/frappe/frappe-bench/sites && python3 -c \"
import json, os
f='common_site_config.json'
config=json.load(open(f)) if os.path.exists(f) else {}
config['socketio_port']='9000'
json.dump(config, open(f,'w'), indent=1)
\""

# 4. Reinstall HRMS
docker exec $CONTAINER sed -i '/hrms/d' /home/frappe/frappe-bench/sites/apps.txt 2>/dev/null || true
docker exec $CONTAINER bench remove-app hrms --no-backup 2>/dev/null || true
docker exec $CONTAINER bench get-app --branch $HRMS_BRANCH --skip-assets hrms

# 5. Build assets
docker exec $CONTAINER bench build --app frappe
docker exec $CONTAINER bench build --app erpnext
docker exec $CONTAINER bench build --app hrms

# 6. CRITICAL: Resolve symlinks for frontend
docker exec $CONTAINER bash -c "cd /home/frappe/frappe-bench/assets && \
  rm -rf frappe && cp -rL /home/frappe/frappe-bench/apps/frappe/frappe/public frappe && \
  rm -rf erpnext && cp -rL /home/frappe/frappe-bench/apps/erpnext/erpnext/public erpnext && \
  rm -rf hrms && cp -rL /home/frappe/frappe-bench/apps/hrms/hrms/public hrms"

# 7. Install + migrate
docker exec $CONTAINER bench --site $SITE install-app hrms || true
docker exec $CONTAINER bench --site $SITE migrate
docker exec $CONTAINER bench --site $SITE clear-cache
docker exec $CONTAINER bench --site $SITE clear-website-cache

# 8. Restart
cd $COMPOSE_DIR
docker compose restart
sleep 10
docker exec $CONTAINER bench version
echo "Update complete!"
# Make it executable (one time only)
chmod +x ~/update-erpnext.sh

Major Version Upgrade Script (v15 → v16, v16 → v17, etc.)

Save as ~/upgrade-erpnext.sh on the server. Usage: bash ~/upgrade-erpnext.sh v16
Safety guarantees: Double-verified backups (local + S3) before touching anything. Automatic rollback if any step fails. HRMS handled cleanly. Zero data loss.
#!/bin/bash
# ============================================
# GrubPac ERPNext Full System Upgrade Script
# Covers: ERPNext + Frappe + HRMS
# Safety: Double backup, verified, auto-rollback
# Usage: bash ~/upgrade-erpnext.sh v16
# ============================================

TARGET_VERSION=$1
SITE="erp.localhost"
COMPOSE_DIR="/home/ubuntu/erpnext"
BACKUP_DIR="/home/ubuntu/backups"
CONTAINER="erpnext-backend-1"
LOG="$BACKUP_DIR/upgrade-$(date +%Y%m%d_%H%M%S).log"

# --- Validation ---
if [ -z "$TARGET_VERSION" ]; then
  echo "ERROR: No version specified."
  echo "Usage: bash ~/upgrade-erpnext.sh v16"
  exit 1
fi

HRMS_BRANCH="version-${TARGET_VERSION#v}"
CURRENT_VERSION=$(grep -oP 'image: frappe/erpnext:\Kv[0-9]+' $COMPOSE_DIR/docker-compose.yml | head -1)

echo "============================================" | tee -a $LOG
echo " GrubPac ERPNext System Upgrade" | tee -a $LOG
echo " Current : frappe/erpnext:$CURRENT_VERSION" | tee -a $LOG
echo " Target : frappe/erpnext:$TARGET_VERSION" | tee -a $LOG
echo " HRMS : $HRMS_BRANCH" | tee -a $LOG
echo " Site : $SITE" | tee -a $LOG
echo " Log : $LOG" | tee -a $LOG
echo "============================================" | tee -a $LOG
echo "" | tee -a $LOG

# --- Rollback function (runs if any step fails) ---
rollback() {
  echo "" | tee -a $LOG
  echo "!!! UPGRADE FAILED — ROLLING BACK !!!" | tee -a $LOG
  echo "Reverting docker-compose.yml to $CURRENT_VERSION..." | tee -a $LOG
  cd $COMPOSE_DIR
  sed -i "s|image: frappe/erpnext:$TARGET_VERSION|image: frappe/erpnext:$CURRENT_VERSION|g" docker-compose.yml
  docker compose pull >> $LOG 2>&1
  docker compose up -d >> $LOG 2>&1
  sleep 15
  docker exec $CONTAINER bench --site $SITE migrate >> $LOG 2>&1
  docker compose restart >> $LOG 2>&1
  echo "Rollback complete. System restored to $CURRENT_VERSION" | tee -a $LOG
  echo "Check log: $LOG" | tee -a $LOG
  exit 1
}

# Enable auto-rollback on any error
trap rollback ERR
set -e

# ========== STEP 1: BACKUP (LOCAL + S3) ==========
echo "[1/11] Creating full backup (database + files + S3)..." | tee -a $LOG
sudo /home/ubuntu/backup-erpnext.sh >> $LOG 2>&1

# Verify backup was created
LATEST_BACKUP=$(find $BACKUP_DIR -name "*database.sql.gz" -mmin -5 | head -1)
if [ -z "$LATEST_BACKUP" ]; then
  echo "ERROR: Backup verification failed! No recent backup found." | tee -a $LOG
  exit 1
fi
BACKUP_SIZE=$(stat -c%s "$LATEST_BACKUP")
if [ "$BACKUP_SIZE" -lt 1000 ]; then
  echo "ERROR: Backup file too small ($BACKUP_SIZE bytes). Aborting." | tee -a $LOG
  exit 1
fi
echo " ✓ Backup verified: $LATEST_BACKUP ($BACKUP_SIZE bytes)" | tee -a $LOG

# ========== STEP 2: SAVE CURRENT docker-compose.yml ==========
echo "[2/11] Saving current config for rollback..." | tee -a $LOG
cd $COMPOSE_DIR
cp docker-compose.yml docker-compose.yml.backup-$(date +%Y%m%d)
echo " ✓ Saved docker-compose.yml.backup-$(date +%Y%m%d)" | tee -a $LOG

# ========== STEP 3: UPDATE IMAGE TAG ==========
echo "[3/11] Updating docker-compose.yml → $TARGET_VERSION..." | tee -a $LOG
sed -i "s|image: frappe/erpnext:v[0-9]*|image: frappe/erpnext:$TARGET_VERSION|g" docker-compose.yml
echo " ✓ All image tags updated" | tee -a $LOG

# ========== STEP 4: PULL NEW IMAGES ==========
echo "[4/11] Pulling new Docker images..." | tee -a $LOG
docker compose pull >> $LOG 2>&1
echo " ✓ Images pulled" | tee -a $LOG

# ========== STEP 5: RECREATE CONTAINERS ==========
echo "[5/11] Recreating containers..." | tee -a $LOG
docker compose up -d >> $LOG 2>&1
echo " ✓ Containers recreated" | tee -a $LOG

# ========== STEP 6: WAIT FOR BACKEND ==========
echo "[6/11] Waiting for backend to be ready..." | tee -a $LOG
sleep 15
# Verify backend is responding
for i in 1 2 3 4 5; do
  if docker exec $CONTAINER bench version >> /dev/null 2>&1; then
    break
  fi
  echo " Waiting... attempt $i/5" | tee -a $LOG
  sleep 10
done
echo " ✓ Backend is ready" | tee -a $LOG

# ========== STEP 7: HANDLE HRMS (CLEAN) ==========
echo "[7/12] Setting up HRMS ($HRMS_BRANCH)..." | tee -a $LOG

# Set default site
docker exec $CONTAINER bench use $SITE >> $LOG 2>&1

# Ensure common_site_config.json has socketio_port (required for HRMS PWA build)
docker exec $CONTAINER bash -c "cd /home/frappe/frappe-bench/sites && python3 -c \"
import json, os
f='common_site_config.json'
config=json.load(open(f)) if os.path.exists(f) else {}
config['socketio_port']='9000'
json.dump(config, open(f,'w'), indent=1)
\"" >> $LOG 2>&1

# Check if HRMS app directory exists and remove it
if docker exec $CONTAINER test -d /home/frappe/frappe-bench/apps/hrms 2>/dev/null; then
  echo " Removing old HRMS app..." | tee -a $LOG
  docker exec $CONTAINER bench remove-app hrms --no-backup >> $LOG 2>&1 || true
fi
docker exec $CONTAINER sed -i '/hrms/d' /home/frappe/frappe-bench/sites/apps.txt 2>/dev/null || true

# Install fresh HRMS matching the target version (skip assets - we build separately)
echo " Installing HRMS $HRMS_BRANCH..." | tee -a $LOG
docker exec $CONTAINER bench get-app --branch $HRMS_BRANCH --skip-assets hrms >> $LOG 2>&1
echo " ✓ HRMS app installed" | tee -a $LOG

# ========== STEP 8: BUILD ALL ASSETS ==========
echo "[8/12] Building all assets (ERPNext + HRMS)..." | tee -a $LOG
docker exec $CONTAINER bench build --app frappe >> $LOG 2>&1
docker exec $CONTAINER bench build --app erpnext >> $LOG 2>&1
docker exec $CONTAINER bench build --app hrms >> $LOG 2>&1
echo " ✓ Assets built" | tee -a $LOG

# ========== STEP 9: FIX ASSET SYMLINKS FOR FRONTEND ==========
# CRITICAL: bench build creates symlinks in assets/ pointing to apps/
# The apps/ directory is NOT on the shared volume, so frontend can't follow them.
# Replace symlinks with actual files so both containers can serve assets.
echo "[9/12] Fixing asset symlinks for frontend container..." | tee -a $LOG
docker exec $CONTAINER bash -c "cd /home/frappe/frappe-bench/assets && \
  rm -rf frappe && cp -rL /home/frappe/frappe-bench/apps/frappe/frappe/public frappe && \
  rm -rf erpnext && cp -rL /home/frappe/frappe-bench/apps/erpnext/erpnext/public erpnext && \
  rm -rf hrms && cp -rL /home/frappe/frappe-bench/apps/hrms/hrms/public hrms" >> $LOG 2>&1
echo " ✓ Asset symlinks resolved" | tee -a $LOG

# ========== STEP 10: INSTALL HRMS + MIGRATE ==========
echo "[10/12] Installing HRMS on site and migrating database..." | tee -a $LOG
docker exec $CONTAINER bench --site $SITE install-app hrms >> $LOG 2>&1 || true
docker exec $CONTAINER bench --site $SITE migrate >> $LOG 2>&1
echo " ✓ Migration complete" | tee -a $LOG

# ========== STEP 11: CLEAR CACHE + RESTART ==========
echo "[11/12] Clearing cache and restarting..." | tee -a $LOG
docker exec $CONTAINER bench --site $SITE clear-cache >> $LOG 2>&1
docker exec $CONTAINER bench --site $SITE clear-website-cache >> $LOG 2>&1
cd $COMPOSE_DIR
docker compose restart >> $LOG 2>&1
sleep 10
echo " ✓ System restarted" | tee -a $LOG

# ========== STEP 12: VERIFY ==========
echo "[12/12] Verifying upgrade..." | tee -a $LOG
echo "" | tee -a $LOG
docker exec $CONTAINER bench version | tee -a $LOG
echo "" | tee -a $LOG

# Verify site loads
SITE_STATUS=$(docker exec $CONTAINER bench --site $SITE show-config 2>/dev/null | grep -c "db_name" || echo "0")
if [ "$SITE_STATUS" -ge 1 ]; then
  echo " ✓ Site is accessible" | tee -a $LOG
else
  echo " ⚠ Site may need attention — check browser" | tee -a $LOG
fi

echo "" | tee -a $LOG
echo "============================================" | tee -a $LOG
echo " UPGRADE COMPLETE: $CURRENT_VERSION → $TARGET_VERSION" | tee -a $LOG
echo " Backup: $LATEST_BACKUP" | tee -a $LOG
echo " Log: $LOG" | tee -a $LOG
echo "============================================" | tee -a $LOG
# Make it executable (one time only)
chmod +x ~/upgrade-erpnext.sh

Fully Automatic Weekly Patch Update

Runs every Sunday at 3:00 AM UTC (after daily backup at 2:00 AM). Automatically pulls latest patch images, backs up to S3, recreates containers, reinstalls HRMS, builds assets, resolves symlinks, migrates, restarts. No manual intervention needed.
KEY: Docker up -d wipes HRMS (not on persistent volume). Script ALWAYS reinstalls HRMS after container recreation. Asset symlinks MUST be resolved to real files for the frontend container to serve them.
#!/bin/bash
# /home/ubuntu/auto-update-erpnext.sh
# Fully automatic ERPNext + HRMS patch updater
# Handles: backup, pull, recreate, HRMS reinstall, build, symlink fix, migrate

SITE="erp.localhost"
COMPOSE_DIR="/home/ubuntu/erpnext"
CONTAINER="erpnext-backend-1"
HRMS_BRANCH="version-16"
LOG="/home/ubuntu/backups/auto-update-$(date +%Y%m%d).log"

echo "=== Auto-update started: $(date) ===" >> $LOG

# Step 1: Full backup (local + S3)
echo "[1/10] Backup..." >> $LOG
sudo /home/ubuntu/backup-erpnext.sh >> $LOG 2>&1

# Step 2: Pull latest images
echo "[2/10] Pulling images..." >> $LOG
cd $COMPOSE_DIR
docker compose pull >> $LOG 2>&1

# Step 3: Recreate containers (HRMS WILL BE LOST - this is expected)
echo "[3/10] Recreating containers..." >> $LOG
docker compose up -d >> $LOG 2>&1
sleep 20

# Step 4: Set default site + ensure socketio_port in config
echo "[4/10] Configuring site..." >> $LOG
docker exec $CONTAINER bench use $SITE >> $LOG 2>&1
docker exec $CONTAINER bash -c "cd /home/frappe/frappe-bench/sites && python3 -c \"
import json, os
f='common_site_config.json'
config=json.load(open(f)) if os.path.exists(f) else {}
config['socketio_port']='9000'
json.dump(config, open(f,'w'), indent=1)
\"" >> $LOG 2>&1

# Step 5: Remove old HRMS traces and reinstall
echo "[5/10] Installing HRMS $HRMS_BRANCH..." >> $LOG
docker exec $CONTAINER sed -i '/hrms/d' /home/frappe/frappe-bench/sites/apps.txt 2>/dev/null || true
if docker exec $CONTAINER test -d /home/frappe/frappe-bench/apps/hrms 2>/dev/null; then
  docker exec $CONTAINER bench remove-app hrms --no-backup >> $LOG 2>&1 || true
fi
docker exec $CONTAINER bench get-app --branch $HRMS_BRANCH --skip-assets hrms >> $LOG 2>&1

# Step 6: Build ALL assets
echo "[6/10] Building assets..." >> $LOG
docker exec $CONTAINER bench build --app frappe >> $LOG 2>&1
docker exec $CONTAINER bench build --app erpnext >> $LOG 2>&1
docker exec $CONTAINER bench build --app hrms >> $LOG 2>&1

# Step 7: CRITICAL - Replace symlinks with real files for frontend
# bench build creates symlinks in assets/ → apps/{app}/public/
# apps/ is NOT on shared volume, so frontend can't follow them
echo "[7/10] Resolving asset symlinks..." >> $LOG
docker exec $CONTAINER bash -c "cd /home/frappe/frappe-bench/assets && \
  rm -rf frappe && cp -rL /home/frappe/frappe-bench/apps/frappe/frappe/public frappe && \
  rm -rf erpnext && cp -rL /home/frappe/frappe-bench/apps/erpnext/erpnext/public erpnext && \
  rm -rf hrms && cp -rL /home/frappe/frappe-bench/apps/hrms/hrms/public hrms" >> $LOG 2>&1

# Step 8: Install HRMS on site
echo "[8/10] Installing HRMS on site..." >> $LOG
docker exec $CONTAINER bench --site $SITE install-app hrms >> $LOG 2>&1 || true

# Step 9: Migrate + clear cache
echo "[9/10] Migrating..." >> $LOG
docker exec $CONTAINER bench --site $SITE migrate >> $LOG 2>&1
docker exec $CONTAINER bench --site $SITE clear-cache >> $LOG 2>&1
docker exec $CONTAINER bench --site $SITE clear-website-cache >> $LOG 2>&1

# Step 10: Restart
echo "[10/10] Restarting..." >> $LOG
cd $COMPOSE_DIR
docker compose restart >> $LOG 2>&1

# Log versions
sleep 10
docker exec $CONTAINER bench version >> $LOG 2>&1
echo "=== Auto-update complete: $(date) ===" >> $LOG
